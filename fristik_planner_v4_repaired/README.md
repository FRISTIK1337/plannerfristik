# fristik.planner — восстановленная версия v4.1

Статический адаптивный планер для GitHub Pages. Проект не требует сборщика, npm или backend-сервера.

## Важное исправление

В предыдущей сборке `app.js` отсутствовали определения `FORM_EXTRA_REQS`, `CASE_TYPES`, `MARKET_ITEMS`, `CARD_DEFS` и `cardCatalog()`. Из-за ошибки JavaScript выполнение останавливалось до подключения обработчиков кнопок. Все определения восстановлены, а приложение проверено в браузерном сценарии.

## Что работает

- Переходы между расписанием, статистикой, коллекцией, магазином и мини-игрой.
- Добавление и редактирование событий, включая ночные интервалы через полночь.
- Режимы расписания «День / Неделя / Месяц».
- Категории, XP, монеты, отметки выполнения и штрафы.
- Коллекция персонажей и 17 форм, кейсы, магазин предметов, карточный альбом.
- Мини-игра «Лови сферы Ки».
- Уведомления браузера, когда сайт открыт и у браузера есть разрешение.
- Резервное копирование и импорт данных.
- Адаптивная мобильная кнопка «Добавить дело».

## Публикация на GitHub Pages

1. Распакуй архив.
2. Загрузи **содержимое** архива в корень репозитория, не сам ZIP и не вложенную папку.
3. Убедись, что `index.html`, `style.css`, `app.js`, `manifest.webmanifest`, `sw.js` и `assets/` находятся рядом в корне проекта.
4. В GitHub открой `Settings → Pages`. Выбери `Deploy from a branch`, ветку `main`, папку `/ (root)` и нажми Save.
5. Дождись успешного deployment. Открой сайт и сделай жёсткую перезагрузку `Ctrl + Shift + R`.

## Обновление после предыдущей сломанной версии

В `sw.js` увеличена версия кеша до `fristik-planner-v4-repaired`; после активации новый Service Worker удалит предыдущие кеши приложения. Если старый интерфейс всё ещё показывается, закрой вкладку и открой сайт заново, затем выполни `Ctrl + Shift + R`. Данные пользователя не сбрасываются: ключ локального хранения `ritmPlanner_v1` сохранён.

## Уведомления

Статический проект показывает напоминания, пока страница открыта. Постоянные push-уведомления после закрытия браузера требуют отдельного сервера отправки push-сообщений.

## Сохранение данных

Расписание, XP, монеты, персонажи, карточки и настройки хранятся в `localStorage` текущего браузера и домена. Перед заменой файлов или переносом на другое устройство экспортируй резервную копию через кнопку «Экспорт». При публикации на GitHub Pages используй тот же адрес репозитория, иначе браузер создаст отдельное хранилище.
